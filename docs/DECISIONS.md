# Решения WibeMusic

## D004 — источник и контракты для широких подборок

- Дата: 2026-11-14; статус: принято.
- Контекст: нужны широкие музыкальные подборки, а доступные источники — в частности публичный Deezer API без ключа. Проверка показала, что `genre/{id}/playlists` не поддерживается (ошибка Deezer 600), при этом доступны `editorial/{id}/charts` и `chart/0/playlists`.
- Решение: использовать read-only маршруты Deezer `artist/{id}/related`, `artist/{id}/radio`, `editorial/{id}/charts`, `chart/0/playlists` и `playlist/{id}`. Hub добавляет небольшие защищённые GET endpoints под `/api/catalog`, кэширует каталожные данные и аннотирует ownership треков текущего пользователя. UI запускает подборки только через существующий общий аудиоплеер.
- Причина: широкая выдача на существующих открытых данных, без нового поставщика/секрета и без изменения аудиосостояния/существующих контрактов. Предупреждение: наличие плейлиста в каталоге не означает доступность полной версии каждого трека; правило запрета preview остаётся обязательным на backend listen.
- Последствия: жанр может вернуть пустой список редакционных материалов; общий чарт даёт альтернативу. Deezer-контент может зависеть от региона и API. Публичные плейлисты ограничены 100 треками по умолчанию, максимальная страница — 1000; pagination URL принимаются только с origin Deezer.
