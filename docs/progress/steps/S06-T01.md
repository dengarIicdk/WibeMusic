# S06-T01 — лёгкий локальный запуск (profiles)

- Статус: DONE (правка и проверка структуры); реальный запуск compose — BLOCKED (нет Docker)
- Дата: 2026-11-13
- Зависимости: S01-T01
- Критерий: optional-профили, повторяемый setup/start, конфигурация проверена.

## Решение владельца

Вопрос задан: вынести embedder (GPU) и tunnel (VPS) в профили. Выбран вариант «Вынести в профили».

## Изменения

- `docker-compose.yml`:
  - `embedder` → `profiles: [gpu]`;
  - `tunnel` → `profiles: [vps]`;
  - `slskd` уже был в `[soulseek]`.
  - `VPS_HOST` стал `${VPS_HOST:-}` (раньше `:?` требовал значение всегда, даже без профиля `vps`). Проверку выполняет `gateway/tunnel/entrypoint.sh` (`: "${VPS_HOST:?}"`), поэтому при включённом профиле без значения туннель не стартует.
- `.env.example`: раздел «Compose profiles» с перечнем `gpu`, `vps`, `soulseek` и примером `COMPOSE_PROFILES=gpu,vps`. По умолчанию `COMPOSE_PROFILES` пустой.

## Базовый запуск (без профилей)

`navidrome`, `hub`, `youtube-pot`. Этого достаточно для локальной работы в LAN. Миксы без embedder работают без «похожести по звуку» (записано в `README.md`).

## Проверки

- Профили распределены, как задумано: базовые — navidrome, hub, youtube-pot; профильные — slskd (soulseek), embedder (gpu), tunnel (vps). Проверено разбором YAML скриптом.
- `docker compose config` — НЕ выполнен: Docker отсутствует. Синтаксис compose не подтверждён запуском.
- Поведение `${VAR:?}` при выключенном сервисе не проверено по документации Docker; поэтому лишнее обязательное поле убрано.
- `HomeMusic.bat` не менялся: он использует `docker compose config --services`, который учитывает `COMPOSE_PROFILES` из `.env`.

## Открыто

- Владельцу: если в `.env` стоит своё значение `COMPOSE_PROFILES`, оно должно включать `vps` (иначе туннель к VPS перестанет подниматься после этого изменения) и `gpu` (иначе embedder остановится). Текущий `.env` не изменялся: в нём могут быть секреты.
- Проверка `docker compose config` и `up` — после установки Docker.
