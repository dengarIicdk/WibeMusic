# S08-T01 — широкие музыкальные подборки

- Статус: DONE (проверки кода пройдены; браузерная приёмка authenticated UI и реального аудио ограничена отсутствием тестовой сессии в доступном экземпляре).
- Начато: 2026-11-14; изменено: 2026-11-14.
- Цель: открыть в WibeMusic широкие read-only подборки из Deezer — похожих исполнителей, радио исполнителя, жанров, редакционных и общих чартовых плейлистов — и дать слушать полные треки стандартным общим плеером.
- Критерий: новые read-only Hub API, обработанные ownership-состояния треков, UI-маршруты и регрессионные тесты; TypeScript/Vite и backend suite проходят.
- Решение: использовать подтверждённые Deezer маршруты `artist/{id}/related`, `artist/{id}/radio`, `editorial/{id}/charts`, `chart/0/playlists`; `genre/{id}/playlists` не поддерживается. Подробно: `docs/DECISIONS.md`, D004.

## Сделано

- `hub/app/catalog/models.py`, `hub/app/catalog/deezer.py`: модели жанров/плейлистов и TTL-кэшированные загрузчики; страницы плейлистов с ограничением 100 треков по умолчанию (максимум 1000) и проверкой origin пагинации Deezer.
- `hub/app/api/catalog.py`, `hub/app/api/schemas.py`: защищённые read-only маршруты похожих исполнителей, радио, жанров, редакционных плейлистов, чартовых плейлистов и страниц публичных плейлистов. Списки треков аннотируются для текущего пользователя.
- `hub/API.md`: задокументированы расширения контракта.
- `hub/tests/support.py`, `hub/tests/test_mix_sources.py`, `hub/tests/test_mixes.py`: проверка маппинга/кэша, пагинации и защиты от внешнего pagination URL, маршрутов и авторизации.
- `web/src/api/types.ts`, `web/src/api/client.ts`: типы/методы API.
- `web/src/pages/CatalogCollections.tsx`, `web/src/App.tsx`, `web/src/pages/Vibe.tsx`: экран подборок, жанровые экраны, страницы плейлистов с воспроизведением/перемешиванием.
- `web/src/pages/Artist.tsx`: радио исполнителя и похожие исполнители; у радио используется существующий `playAll`/единый плеер.

## Ограничения и продолжение

- Браузер открыт на Multipass-стеке `http://172.27.160.225:8080/#/catalog/genres`; app отвечает, но переходит на экран входа. В этой сессии нет тестовых credentials, поэтому нельзя подтвердить авторизованные подборки или проигрывание. В консоли только ожидаемый `401 /api/auth/me` для гостя.
- Попытка открыть устаревший адрес из предыдущего checkpoint `172.27.171.55:8080` вернула 502; проверен актуальный IP через `multipass list`.
- Ruff не доступен в тестовой venv; полный suite и `compileall` проходят.
- Для полноценной визуальной приёмки нужен безопасный доступ к тестовой учётной записи и живой Deezer, затем проверить списки/карточки, воспроизведение полной версии треков и навигацию, не публикуя credentials.
